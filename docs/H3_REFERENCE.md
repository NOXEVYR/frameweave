# H3 多模态参考工作流

Phase7O 源码候选。此功能建立标准工作流包；创建本身不上传素材、不运行模型。实际页面和 H3 权重推理仍须单独验收。

## 创建与使用

1. 在「视频生成」选择「H3 · 多图参考视频」，设置模型、提示词和采样参数。
2. 展开「创建多模态参考工作流」，选择图片、视频、独立音频的槽数。可只用视频或音频，不要求添加占位图片。
3. 仅对确实有声音且需要声音参考的视频勾选「使用声轨」。同一加载节点提供画面和配套声轨，避免错接到其他视频。
4. 点击「建立工作流并选择外层参数」。在标准工作流包窗口检查名称和外层参数，保存后添加到画布。
5. 在命名输入处上传素材，或将素材节点、上游生成结果连接到对应图片、视频、音频端口。模型、编码器、VAE、LoRA、提示词和采样参数保留外层控件。
6. 「进入工作流」可调整内部结构，再使用原有接口管理与差异确认同步外层。编辑源码、修改显示名称和改变输入身份是不同操作；新增/删除输入应检查连线变化。

旧图片预设和当前工作台草稿不会被替换；旧参考图片也不会静默复制到新槽位。新节点中的素材与后端归属按通用媒体协议检查。缺模型或素材可以保存为待配置草稿，运行前仍需通过当前引擎校验。

## 输入与编号

最大槽数取客户端上限与实时后端声明的较小值：图片 9、视频 3、独立音频 3。视频声轨和视频按内部同号插槽配对，不作为独立音频替代。

提示词使用 `<Picture 1>`、`<Video 1>`、`<Audio 1>`。图片与视频各自从 1 编号；启用的视频声轨先按视频顺序占用 Audio 编号，独立音频随后编号。例如只有视频 2 启用声轨时，它对应 `<Audio 1>`，首个独立音频对应 `<Audio 2>`。装配结果提供逐槽映射。

## 视频读取与资源控制

当前已验证的本机加载协议为 VHS_LoadVideo：24 fps、每帧读取、format=None；同源 AUDIO 输出用于配套声轨。仅存在 LoadVideo/GetVideoComponents 不证明具备帧率转换，因此不会自动作为等价替代。未选择视频或音频时，不要求安装相应加载器或声明未用输入组。

参考视频默认宽高不超过 736×416，或使用更小的输出宽高；两个非零尺寸会让加载器中心裁切后缩放，可能截掉边缘或放大小视频。外层可调参考宽高、读取帧数上限和跳过起始帧；初始帧数上限不超过输出帧数与 362。24 fps 和逐帧读取在初始外层合同中固定，避免无意改变时间语义。

内部自由改图后，普通节点 schema 校验只能确认类型、范围及连接，不能证明仍遵循 H3 的时间语义，也不会自动重算之前的读取帧数上限。修改输出时长或内部加载器后应检查参考片段设置。无声视频勾选声轨会在解码时失败；装配阶段不假装已验证文件内容。

## 本地 API

`POST /api/h3-reference/prepare` 使用现有 Host/Origin/CSRF 校验，正文必须是 `backend_url`、`preset_request`、`layout` 三项：

```json
{
  "backend_url": "http://127.0.0.1:8188",
  "preset_request": {"kind": "h3_ref", "positive": "<Video 1> 的动作与 <Audio 1> 的声音"},
  "layout": {"image_count": 0, "videos": [{"soundtrack": true}], "audio_count": 0}
}
```

返回 `prepared` 只表示标准包已装配，`pending` 是待配置或待验证内容；`blocked` 返回具体不兼容项且没有半成品包。读取真实 schema 前后检查后端身份。该接口不保存、上传或执行；调用方随后使用已有包保存、编译和幂等生成接口。

## 本阶段证据

六种输入组合在本机实时 schema 下均可装配、按标准包保存/导出/重新读取，最大组合产生 15 个独立素材字段。临时 HTTP 验证标准包的外层填写、内部准备、编译和固定帧率约束。

真实无权重解码任务使用新建合成输入：30 fps 转成 24 fps、22 帧；有声/无声视频各一份，配套声轨约 0.9167 秒，独立音频 0.5 秒。此证据只覆盖读取和保存，不代表 H3 模型生成、GPU 速度/质量或实际桌面页面验收。
