# 任务查询与取消

画布、图片/视频/音频工作台、MCP 与可选 Hub worker 共用同一份任务记录。每个任务保留原引擎、原请求编号、参数和产物。任务状态与取消请求状态分别显示。

| 任务状态 | 含义 | 可做的操作 |
| --- | --- | --- |
| queued / running | 原引擎仍列出任务 | 查询；支持时请求安全取消 |
| unknown | 原引擎不可读取，或任务不在队列且没有终态历史 | 查询原任务；保留原编号与参数 |
| completed | 原任务历史确认完成 | 查看、传递产物；复用参数 |
| failed | 原任务历史确认执行错误 | 查看错误与已有产物；修改参数 |
| cancelled | 原任务错误历史包含同 prompt_id 的 execution_interrupted | 查看已有产物与原参数 |

“取消已请求”仅说明请求已送达。ComfyUI 的定向取消回复仍可能早于实际停止，任务也可能在取消生效前自然完成。完成时保留结果并说明取消未阻止本次生成，不改写成已取消。旧引擎仅支持按 ID 删除排队任务时，删除回复和队列消失也不构成终态证据。运行中任务无法定向取消则明确显示能力不足，不使用共享全局中断。

取消意图先保存再发送。重复点击、回复丢失、持久化失败和客户端重启都保留同一取消编号，未确认时不重发。取消接口返回当前任务及 `cancellation`，其中 `state` 可为 `requesting`、`requested`、`uncertain`、`unavailable`、`confirmed`、`completed`、`failed`。其中前三种要求继续查询；`unavailable` 允许用户明确重试安全取消。

`POST /api/jobs/{job_id}/refresh` 使用空 JSON 与当前 `X-FW-Token`，只读查询任务自己的原引擎，返回当前任务。MCP 使用 `fw_jobs` 的 `{ "job_id": "...", "refresh": true }`，不能同时带 `request_id`。刷新不会提交生成、触发取消或切换引擎；不接受任意任务或后端地址。

`unknown` 不是失败或取消，不能以“再次生成”按钮或新请求编号重试同一未确认任务。用户仍可主动创建独立任务。未结束任务会阻止切到其他引擎及安全退出；若当前引擎已与任务不符，可以返回所有未结束任务共同所属的原引擎。

工作流调度器发现某步的新取消编号时暂停后续步骤，即使该任务最终自然完成，也先让用户点击“查询并继续”。用户的确认随运行记录持久保存，新的取消编号需要再次确认。状态未知时后续步骤持续暂停，保持同一原任务与请求，不重新生成上游。

旧版缺少终态证据的 cancelled，以及明确因队列缺席或切换引擎写入的 failed 记录恢复为待确认；真实执行错误不据此改写。后台只读查询原历史；历史已清除时可能持续待确认。当前没有自动遗忘或强制终结此类任务的功能，避免以清记录方式误触发重复生成。
