用户可以将新的 ComfyUI 工作流直接导入为可组合的画布节点，自动获得有依据的常用输入；进入内部调整结构后，外层控件与连线可检查、同步和重新绑定。图片、视频、声音和音乐共用媒体与工作流能力。复杂流程不退化为只有一个“生成”按钮，也不要求每个工作流开发独立适配器。

功能完整、执行准确与交互流畅优先。复用本机模型与现有引擎，按需加载编辑器，控制缓存和扫描范围；不以最小安装体积为由省略必要功能。

## 一套合同，五类状态

1. **原始文档**：保留原始 JSON、来源格式和内容标识。导入是数据操作，不执行任务，不改写用户原文件。
2. **内部草稿**：实际 ComfyUI 编辑器保存的完整结构，包含子图、被旁路或未连接的分支。草稿与可执行状态分开；缺模型不能阻止保存草稿。
3. **外层接口**：稳定字段 ID、内部目标路径、类型、角色、名称、控件/端口呈现、默认值与输出身份。自动识别和手动外露共用这一合同。名称可改，身份不可按名称或位置猜测。
4. **编译结果**：当前后端 schema 和实际前端生成的执行图、能力诊断及接口差异。原文与编译产物分开，兼容迁移可追溯；不静默丢弃未知真实输入。
5. **执行计划**：冻结本次参数、后端身份、所选输出及其祖先依赖闭包、媒体归属和请求 ID。只校验实际参与执行的依赖；切换输出后重新检查，不因无关悬空分支拒绝有效任务。

现有 v1 工作流包和画布字段保持兼容，优先扩展已有模块，不引入另一套平行数据系统。大格式升级必须证明旧数据迁移与往返保持。

多路文本拼接属于改变执行语义的扩展：普通画布和运行记录继续写 v1；含拼接规则或重复贡献身份的画布写 `frameweave.canvas.v2`，其运行记录写 `frameweave.workflow-run.v2`。新版本读取两者，旧版本应明确拒绝新语义，不能丢掉规则后悄悄执行成替换文本。数据目录、浏览器存储键和工作流包标识保持不变。

## 接口编译与同步规则

- 根据实时节点 schema 识别标量、模型、编码器、LoRA 和标准上传字段；常用项自动推荐，其他项在接口管理中可选择。不能仅按工作流名称或节点显示名推断协议。
- 文件名上传槽与内部 IMAGE/VIDEO/AUDIO 张量、文件路径、URL 分开。场景、人物、首帧、尾帧等角色属于独立且稳定的槽位；输出分支和批次也明确记录。
- 内部编辑返回时进行基线、外层值和内部值的三方比较。未变目标保留原值、名称、外露选择和连线；新增项推荐；删除/换型显示影响；冲突或重绑由用户明确选择后原子应用。
- 子图用实际实例路径映射控件；多个实例内相同子节点 ID 不能互相污染。无可靠映射保留外层值并说明具体目标，不能截尾猜 ID。
- 无显式输出选择时使用全部已声明的输出节点；显式选择只执行对应依赖闭包。不存在有效输出时说明原因，不猜测任意终点。
- 结构、依赖、参数、素材和后端状态分别诊断。缺插件与客户端兼容缺口分开；可导入、可编辑、可编译和可运行分开显示。
