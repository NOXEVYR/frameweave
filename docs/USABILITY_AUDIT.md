# 整体可用性检查

## 0.11.4 反馈复查

0.11.3 的检查没有覆盖离线导入、素材节点直接选择文件、按端口拖线和内置预设进入内部工作流，不能把当时测试通过理解为完整画布体验已验收。本轮将这些用户实际遇到的阻断纳入独立回归：图片与视频本地持久存储、导入即时预览、连续替换竞态、多输入顺序、输入类型检查、结果继续编辑、内外层工作流同步，以及真实进度通道。

视频跨节点传递使用同一引擎已登记的输出，按视频类型筛选序号，验证包字段和后端节点接口；中间预览只是后端提供的当前帧，不等于最终生成质量。保存的旧预览不决定新运行的输出类型。图片和视频类型不匹配在连线时拒绝，避免先生成再发现无法传递。

新增实际浏览器检查使用隔离数据；真实 ComfyUI 前端的无生成导入/调参验收和 GPU 生成分别记录。最新计数与范围见[验证记录](VALIDATION.md)，操作说明见[素材与实时生成指南](CANVAS_MEDIA.md)。以下保留 0.11.3 历史检查。

## 0.11.3 历史检查

检查日期：2026-09-28。目标是验证“导入与调参 → 提交 → 查看产物 → 复用 → 保存 → 恢复”的完整过程，并检查失败时是否保留数据。检查包括源码审阅、独立复查、单元/API 回归与实际浏览器操作。浏览器使用隔离的模拟推理后端；未操作个人模型或提交 GPU 生成。

## 本轮修复

| 问题 | 处理与验证 |
| --- | --- |
| 一条任务历史损坏会让全部历史不可见 | 逐条恢复有效记录，另存原始文件；启动时提示恢复结果，设置中可以重新查看。测试覆盖损坏 JSON、异常类型、非有限时间及备份失败。 |
| 历史备份失败后仍可能提交新生成或上传文件 | 提交到后端之前阻止相关写入，保留原文件并提示修复磁盘问题后重启。测试确认后端调用数为零。 |
| 上传的参考素材在客户端重启后预览失效 | 持久保存素材登记及所属后端，恢复稳定的预览地址；HTTP 测试确认重启前后返回相同图片字节，临时产物也保留正确存储类型。 |
| 浏览器草稿写入失败时仍可能退出 | 应用内退出/更新前保存失败会取消操作；直接刷新触发离开确认。实际浏览器验证取消后保留页面；本地版本保存失败也保留名称和弹窗。 |
| 超过 200 个画布后找不到早期记录 | 本地版本库增加分页和全库搜索，工作流配置库支持加载更早记录；205 条隔离记录验证较早版本可见、可搜索。 |
| 保存一个配置会受无关坏工作流影响 | 只打包目标节点和直接上游提示词涉及的定义，保留正负提示词当前值；媒体引用清空后重新上传或连接。 |
| 已满画布载入配置仍先写入定义 | 在包与内部工作流写入前检查容量；异步返回后再次检查画布身份与容量，防止写入另一张画布。 |
| 音频上传中切换包、分类、后端或字段会污染新草稿 | 上传绑定原草稿、包、字段和后端；过期回包不能写入新状态。同字段连续选择采用请求序号，逆序回包只保留最后一次选择。 |
| SDXL 切换后端后，外置编码器仍显示旧候选 | 候选从当前后端重新读取；旧值保留并显示“当前列表未找到”，由用户明确改选或清空。 |
| 音频格式说明与实际支持不一致 | 上传帮助和错误统一为 WAV、MP3、FLAC、OGG。输出格式支持与输入上传格式分别处理。 |
| 损坏的更新暂存包导致反复重试失败 | 保留原暂存文件，在新目录重新下载并继续校验摘要与归档；界面显示恢复说明。使用合成下载测试，未下载或安装真实更新包。 |

## 未清零的具体限制

- 第三方原生编辑器扩展不是客户端自带功能。此前发现的旧 Text 节点缺失、Crystools 监控请求及 Manager 扩展问题，本轮没有安装或替换插件，不能标记为已修复。
- 配置载入期间若其他操作切换画布或填满容量，会中止放入节点；已经登记的定义保留在包库。尚未实现跨多个接口的原子事务，不会自动删除可能被其他画布引用的定义。
- 输入素材登记当前限 10,000 条，达到上限时在上传前提示。尚未提供可视化的登记归档/清理器；不要手工删除仍在使用的素材和记录。
- 不能用本轮模拟结果判断算法速度、视频质量、声线或音乐质量。相关真实模型验收应按模型/加载器/工作流/后端版本分别记录。

## 后续每次更新的回归基线

1. 导入有效与缺依赖工作流；外层改参数；内部改结构；检查接口同步、明确阻断和原文保留。
2. 生成一次；核对只提交一次；查看/播放结果、定位文件、复用参考素材。
3. 切换工作区与引擎；核对独立草稿、候选刷新和素材归属；验证迟到响应不覆盖新选择。
4. 保存命名版本、导入导出、刷新与重启恢复；注入损坏记录、写入失败与离线，确认没有静默丢失或自动重提。
5. 检查低高度弹窗、关闭入口、快捷键、画布手势；运行 Python/Node 全量回归。
6. 构建后核对嵌入文件，并单独记录 EXE、真实推理和公共下载的验收状态。

完整测试数量及版本交付状态见 [验证记录](VALIDATION.md)。本表是一轮有明确范围的检查，不能作为“所有功能均已完善”的承诺。
